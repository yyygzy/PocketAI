## 怎么跑

- **A 组**只读目视，不改任何数据，约 5 分钟。
- **B 组会动数据**：开始前**先手动做一次全量备份**（设置 → 备份 → 本地备份）。
- **C 组需要额外环境**（第二台机器 / 真实 U 盘 / 真实云盘账号），优先级最低。
- 建议顺序：B6（升档）→ B8（档位自愈）→ B9（合并）→ B15/B16/B17（本批新增）。
- **回传格式**：每条一行 —— `编号 / 通过 或 异常 / 异常时贴你实际看到的文字或截图`。
- 标记：`⬜ 待跑` / `✅ 通过` / `⚠️ 异常` / `🔁 已进 CI（仍建议目视排版）`

## C. 需要额外环境（有条件再做，优先级最低）

- **C1 ⬜ 真·异机备份恢复**：机器 A 升到 2^17 档后做加密备份 → 机器 B（或把 `data` 目录整体拷到另一台/另一份便携盘实例）用备份密码恢复 + 合并。预期：**不再报「备份密码错误」**，恢复后数据可读。这条正是 Batch-7 那个回归的验收点。
- **C2 ⬜ 真实 U 盘符号链接拦截**：在 `data/` 内造一个指向 `data/` 外的符号链接，让文件模块去读 → 应报路径校验失败而非读到外部内容。
- **C3 ⬜ 真库检索召回（SEC-18）**：知识库页「检索测试」面板跑那 10 条中文查询，看回显的 `全文命中`（bm25Hits）是否 >0——改前恒为 0。
- **C4 ⬜ 真实云盘的完整备份链路**：在设了主密码（db 模式）的机器上，对**真实**坚果云/Nextcloud 依次跑「上传备份 → 增量备份 → 刷新列表 → 下载恢复（或合并扫描）」四条。预期全部成功。这条覆盖的是 SEC-35 之后**只剩主进程内部**拿明文口令的通道（`upload/incremental/list/restore/merge/delete` 都走 `loadWebDAVConfig()`，不经 IPC，故单元测试证明不了它们在真机上没被改坏）。
