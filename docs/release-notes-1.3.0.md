# 墨匣 1.3.0 发布说明

> 状态：代码已提交并推送至 `main`；Windows 安装包（NSIS / Portable）已构建。尚未打 `v1.3.0` 标签、尚未发布 Release。
> 变更区间：`v1.2.8..HEAD`。

## 安装前请先看：安装包未签名

本次三个平台的包**都没有代码签名**（Windows 无证书，macOS `identity` 为 `null`）。这不是安装包损坏，而是签名成本尚未落地，请按下面的方式放行。

### Windows

- 首次运行 `Moxia-1.3.0-x64.exe` 时，若该文件是**从浏览器下载**的，SmartScreen 会拦一次：
  「Windows 已保护你的电脑」→ 点「更多信息」→「仍要运行」。
- 用第三方下载工具/命令行下载的文件可能不带「来自 Internet」标记，就不会出现这一屏；这属于正常现象。
- 安装过程中 SmartScreen 可能再拦一次（安装器本体），处理方式同上：更多信息 → 仍要运行。
- 部分国产安全软件（腾讯电脑管家、360 等）会提示「未知发布者」或「可疑程序」，需手动加入信任。
- 便携版 `Moxia-1.3.0-Portable-x64.exe` 每次从新位置启动，可能重复出现同类提示。

### macOS

- 首次打开会提示「无法打开，因为 Apple 无法验证」：到「系统设置 → 隐私与安全性」点「仍要打开」，或对 app 右键 → 打开。
- 若仍被拦截，可对 dmg 内 app 执行 `xattr -dr com.apple.quarantine /Applications/Moxia.app` 后再打开。

### 校验完整性（不受未签名影响）

`latest.yml` 里给了安装包的 `sha512`，可自行核对下载是否完整：

```powershell
Get-FileHash .\Moxia-1.3.0-x64.exe -Algorithm SHA512
```

## 主要变化（1.2.8 → 1.3.0）

### 一、对话与 Agent 执行

- **按轮次工具授权（per-run 工具授权）**：每一轮可以临时收窄这一轮能用的工具面，落库字段 `tool_scope_json`，迁移 v75；`'*'` 只覆盖内置工具，MCP 一律逐条显式授权。
- **Agent 模式按会话记住**：`agent_mode` 成为唯一能力位，迁移 v59 回填历史会话。
- **能力检测（工具调用）**：探针 + 运行时可观测结果共同判定一个模型能不能被委派；只认原生 `tools`，请求失败不会改写已有判定。
- **运行记录与续跑**：持久化阶段检查点，中断后可续跑并跳过已完成的工具步；失败档只对 model 阶段开放按步重试。
- **运行中插话**：入队（本轮结束自动发）与立即插队（在步边界收下）两种方式。
- **金额预算**：触顶时在 Agent 循环边界优雅收尾，不再把整轮打成失败；后台规划/总结等调用也计入用量。
- **子代理会话可打开**：按进入前轮次定位返回；委派步骤标出角色名。
- **工具结果落文件**：大结果改为「落文件 + 给引用」，`agent_traces` 补参数、返回、模型三列。
- **改写文件前先点头**：`fs_write` 带 diff 预览、accept 与还原。
- **输入区收成一颗「+」**：附件、执行设置、工具策略都在这一颗里，工具策略屏只读展示「每个工具能碰什么」以及当前助手实际生效的工具面。
- **工具按组按需装载**：MCP 工具超量时降级为装载上限，不再一次全塞进上下文。

### 二、技能、MCP 与能力中心

- **技能包校验和**：导出带 `sha256`，导入时校验和不对直接拒绝；导入前还会做静态扫描并留审计痕迹。
- **配置包导入**：包级 `sha256`、同名配置并存不覆盖、导入时清空凭据；粘贴导入走同一条服务。
- **技能第三层**：技能落盘 + 逐条常驻开关 + `load_skill` 工具；常驻技能有 32KB 总预算。
- **技能市场**：索引与安装改走 GitHub Contents API（raw 仅兜底）；技能分类与标签落库（v63）。
- **在线技能目录包**：registry 条目可带 `manifest` 清单，一次安装 `SKILL.md + references/scripts/assets`（此前在线只能装单文件）。清单先做路径/体积预检，资源逐文件同源走 `safeFetch`（SSRF/IP pin 不降级），有 hash 就逐文件校验；没给 hash 的会在结果里明说"未逐文件校验"。
- **技能许可证透明**：上游 `license` 声明不再混在"本应用不执行的字段"里被静默忽略——解析层识别并在导入成功时上屏告知（如 `Apache-2.0`），同时提示"仅告知、再分发请自行核对"；不入库、不注入。顺手修了 `metadata:` 缩进块里的 `author` 被误读成技能作者的问题。
- **MCP 站点级出网限制**：按站点收口出网，dry-run 观测补上 MCP 口径。
- **MCP 可观测性**：调用日志落库、带密钥的配置模板、手工试运行二次确认与参数示例、按调用审计；模板与鉴权头可管理，支持导入与重连。
- **能力中心**：新增聚合入口，把技能与 MCP 放在同一屏；补「停止」并清理历史孤儿账。

### 三、知识库与检索

- **语义检索增强**：每个库可设相似度阈值，检索结果带余弦相似度；无关片段不再挤进 topN。
- **多库附件与图片 OCR**：附件可入库到多个知识库，图片走 OCR 后参与检索。
- **降级留痕**：六路检索降级都会留痕，不再静默少召回。
- **评测集**：数据结构与判分、运行器接上真检索、界面入口可跑；一次跑完把两个数并列报。
- **文档管理**：文档列表支持批量重试、批量删除/停用。

### 四、首页、备份与维护

- **首页挂备份状态与恢复入口**：备份最近的结论直接上首页；便携版会提示有新版本。
- **备份验证**：三态结论并入故障诊断卡；恢复替换按差集清理目录。
- **内置维护任务开闸**：维护任务可单独开关，间隔可配。
- **数据健康**：向量库指标换成真实索引规模，新增 `agent_traces` 规模观察口；缓存那一格可「打开数据目录」（只读跳转，不做删除）。
- **缓存清理边界**：只清 `userdata` 那棵活缓存，遗留缓存另走清扫通道。
- **冷数据**：按会话落盘、随会话删除；恢复时按差集清目录，体积与清理失败都会上屏。

### 五、界面与使用体验

- **主题预设**：改为内置预设注册表（深海蓝、暖砂、护眼绿等），主进程与首帧脚本按 id 取用，建窗即用对的底色，不再闪一下浅色/深色。
- **全局快捷键中枢**：一套快捷键收口，含标签页快捷键。
- **会话管理**：置顶、归档、未读落库并在侧栏提示、搜索增强（跳转定位高亮 + 日期筛选 + 分页）、会话备注。
- **导出**：单条/多选批量导出（Markdown / HTML / PDF / 长图）。
- **输入区**：粘贴附件、`@` 引用知识库、代码块一键复制与折叠、提示词片段库、会话智能标题。
- **助手货架化**：默认「我的」不列内置，启用挂进列表不占额，复制才落可编辑副本；内置助手名/描述/欢迎语四语本地化。
- **设置页重排**：拆为六个页签，新增能力（MCP）与连接（IM 网关）分区。
- **翻译/绘图的模型选择口径统一**：两页的模型下拉与候选只列「设置 → 模型与用量」里勾选启用的模型，不再把 `/models` 拉回来的全量摆给用户；历史回填中已停用的模型保留一条禁用项（看得见、选不了）。从未配置启用白名单时仍显示全部，老库升级零感知。
- **浏览器自动化模板升级为 Playwright MCP**：原 puppeteer 模板换成微软官方 `@playwright/mcp`，用无障碍树定位元素（比截图定位更稳），支持点击/填表/截图与连接已有浏览器复用登录态；仍属高风险模板，敏感动作逐次确认。
- **终端工作目录不再看"从哪启动"**：手动终端按「显式指定 > Agent 工作目录 > 主程序目录（便携版/开发态）/ 用户主目录（安装版）」选落点，不再继承进程启动目录；无效或不可写的候选自动退档。终端页现在显示本次 shell 的实际工作目录，点击即可改路径（回车确认，清空恢复默认），切换会重启终端。

### 六、文档生成与导出

- 结构化 spec 生成 DOCX / XLSX / PPTX；XLSX 公式单元格写入缓存值；Markdown 产物可导出 PDF。

### 七、安全与稳定性

- **主密码强度**：scrypt 档位版本化，主密码参数升到 2^17（SEC-Batch-7）。
- **出网清单**：出网出口从代码枚举成一张屏，覆盖测试兜住新增调用点。
- **审批与凭据**：审批决定落库（`approval_events`）、参数脱敏、删会话级联；凭据加密轮换与密钥脱敏。
- **「读不到」收口**：全站大批量把静默失败改成「说得出 + 给一次重试」；读不到默认值时明确写「当前显示的是默认值」，不再把失败演成正常。

## 升级说明

- **数据位置（1.3.0 起变了）**：没有共享标记时，安装版的数据改到 `%APPDATA%\Moxia\data`（macOS 为 `~/Library/Application Support/Moxia/data`，Linux 为 `~/.config/Moxia/data`），不再放在安装目录里——这样覆盖安装/应用内全量更新都不会再碰用户数据。便携版与 AppImage 保持自包含，数据仍在 exe 旁边。若启动器目录或其父目录有 `pocketai.json` 标记，则改用标记指定的共享数据根，见下方「跨平台共享数据根」。
- **老用户升级时安装器先搬数据**：Windows 安装包在覆盖升级前，会先把旧安装目录里的 `data\` 整个搬到 `%APPDATA%\Moxia\data`（搬不动就用复制兜底），再让旧卸载器清理程序文件——否则旧卸载器会连数据一起删掉。搬完后新位置留一份 `migrated-from.json`。
- **首次启动还有一层兜底**：如果安装器没能搬成功（例如跨卷复制失败），1.3.0 首次启动会把旧安装目录下的 `data\` 复制到新位置，逐文件核对大小、对 `app.db` 与 `config.json` 做 SHA-256 校验，确认新位置可读后才删除旧副本。中途失败时原数据完整保留在旧目录，程序会弹窗说明并退出，不会带着空库继续启动。
- **升级前仍建议备份**：迁移是一次性整目录复制，大库/大附件会让升级/首次启动明显变慢（等待期间不要强杀进程）。
- **便携版的数据语义**：替换或覆盖便携版 exe 本身不影响 `exe 同目录\data`；但删除/移动整个文件夹会连数据一起走，把 exe 拷到新文件夹等于开一份全新数据。便携版请继续用应用内备份兜底。
- **卸载不删数据**：卸载程序只删程序文件，`%APPDATA%\Moxia\data` 里的数据会保留，卸载界面会写明该路径；重新安装后直接沿用。需要彻底清除时请手动删除该目录。
- **迁移**：启动时自动执行数据库迁移（到 v75），无需手动操作。
- **更新通道**：安装版可在应用内检查并下载更新；便携版只能查「有没有新版本」，需到发布页手动下载替换，应用内不会自行下载或替换文件。

### 跨平台共享数据根（移动硬盘 / 双系统）

1.3.0 起支持把同一份数据放到移动硬盘上，Windows 与 Linux 客户端共用；无需设置环境变量，也不用手动复制数据。

**用法**：在启动器所在目录（或其任一父目录，通常是移动硬盘根目录）放一个 `pocketai.json`：

```json
{
  "version": 1,
  "dataDir": "data"
}
```

- `version` 必须为 `1`；`dataDir` 必须是相对路径，且不能逃出标记所在目录（防止误配把数据写到盘外），省略时默认为 `data`。标记无效时会被忽略并回退到原有落点。
- 启动器从自身目录向上逐级查找该标记，找到后数据根就是 `<标记目录>/<dataDir>`。Windows 安装版、Linux deb、Windows Portable、Linux AppImage 均适用：只要两个平台的启动器能找到同一个标记，就共用同一份数据。
- 数据根解析优先级：`POCKETAI_DATA_DIR` 环境变量 > `pocketai.json` 标记 > `POCKETAI_APP_ROOT` / 开发态（仍用 `APP_ROOT/data`）> 便携形态（`APP_ROOT/data`）> 安装版用户目录（`appData/Moxia/data`，兼容回退）。
- `runtime/`（Python venv、Ollama 二进制、原生模块、MCP 可执行程序）仍按平台隔离，不放进共享数据根。

**跨平台引用**：入库的附件、知识库源文件、授权文件、MCP 路径等改存 `${DATA_DIR}` / `${APP_ROOT}` 形式的相对引用，不再写死盘符；换系统后按当前数据根重新解析。旧版本留下的绝对路径在读取时按历史数据根（含 `Moxia/data` 段）映射回当前数据根，映射不了的保持原样。

**平台差异配置**：与平台绑定、不能跨系统共用的设置（如 MCP 命令、运行时路径、系统证书路径）放在 `data/profiles/<platform>/override.json`（`win32` / `linux`）。启动时按当前平台合并，profile 中的值优先于 `data/config.json` 中的通用设置；主题、模型、会话、知识库、密钥等通用设置继续放在共享配置里，两端一致。

**并发锁**：共享数据根同一时间只允许一个客户端写入。`data/.lock` 记录平台、主机名、PID 与心跳时间，正常退出时释放；若另一个实例正在使用，程序会弹窗提示「数据目录已被占用」并退出，不会两个系统/进程同时写同一份 SQLite。心跳 15 秒、超过 60 秒未续期视为陈旧锁并接管（避免跨机器按 PID 误判）。

**迁移**：首次在共享数据根启动时，若本机 `appData/Moxia/data` 已有数据而共享目录为空，会自动把本机数据复制过去，逐文件核对大小并对 `app.db` / `config.json` 做 SHA-256 校验，成功后写 `migrated-from.json`（`kind: installed-to-shared`）。复制成功后**保留本机副本**，拔盘后仍可用本机数据启动；复制失败时共享目录的半成品会被清理，本机原数据不变。

## 已知问题

- 安装包未签名，见文首说明。
- 便携版不支持应用内下载更新。
- 应用内「检查更新」读到的最新正式版仍为 v1.2.8 时，1.3.0 会显示「已是最新」——这是版本比较的正确结果，等 v1.3.0 的 Release 发布后才会提示更新。
- **覆盖安装清空数据**：已在 1.3.0 修复（数据移到 `%APPDATA%\Moxia\data` + 首次启动自动迁移），见「升级说明」。
- **冷启动白屏**：早期打包版在本机实测出现过窗口已开、只显示菜单栏、正文空白 85 秒以上仍不恢复（日志连续 5 次「页面加载失败」，随后无恢复记录）；另两次启动在 40–60 秒后才出首帧。该问题已由 `fe2669c` 修复（硬件探测由同步改异步、窗口 `show` 后延迟触发，启动路径不再被 CIM 查询钉住）。修复后尚未在本机做打包版复测，仍建议发布前按同一场景复核一次。
- **打包版没有托盘**：日志 `tray icon not found ... app.asar\build\icon\icon-256.png`，托盘初始化被跳过（1.2.8 同样存在，非本版新增）。
