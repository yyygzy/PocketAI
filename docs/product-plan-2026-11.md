> 修订基准：历史为 2026-11-07 工作树（截至 V4-Iter-443）；最近回写 2026-11-27，当前源码 HEAD `cc5aa88`。行号会随代码漂移，所以关键断言同时写函数名／常量名；本文只把能在 `src/` 里回源的事实当作论据。

## 0. 一句话定位

**PocketAI 是一台装在自己电脑里的、可审计的 AI 工作台：模型你选，数据你留，工具你批，授权买一次就归你。**

它不是更便宜的 ChatGPT 桌面壳，也不是云端代跑 Agent。用户选它而不是 ChatGPT 桌面，只应该因为三件事：模型与推理可以完全归自己（BYOK／本地）、资料与执行不离开本机、每个工具动作可审批可回溯。换不来这三样，这个产品就没有存在理由。

**现状判断（2026-11-27 回写）：普通聊天与 Agent 合流、可回放执行层与商业承诺的边界仍按本文口径；知识库评测与技能模块五阶段已全部落地，P1-3／P2-2／出网 v2／冷 blob 引用计数／P2-3 v82 审计等后续事项见第 4、5 节与第 13 条回写，相关“覆盖率统计未做”“技能路由未做”“无 allowlist”“没有引用计数”“未做自动续跑”“导入结果无审计”等旧描述已不再成立。**

## 2. 产品诚实性：界面在沉默或说谎

P0-2 原本是一条，里面混着五种成本不同的东西。本文把它拆成 2a／2b／2c，**拆开的理由不是项目管理偏好，而是防止季度末出现“这条做了一半但看起来做了”**：2a 只动文案与渲染分支，2b 要跨检索→落库→渲染，2c 要动表与出网枚举；捆在一起时，最容易发生的就是 2a 的文案先上、2b／2c 的数据层没跟上，而界面已经“看起来有了”。

### 2.1 2a：纯文案与空态（已完成，尾巴已修）

- **单价表为空不显示金额**：`UsagePanel.tsx` 的金额位、超额判定、进度条都按“价表非空”分档；价表为空时只显示“未配置单价”，不再出现裸 `¥` 或 `¥0`。同时收口了费用趋势、明细弹窗合计、问答气泡用量三处同形裸符号。
- **Linux 取词不支持明说**：`utils/shortcuts.ts` 的 `isLinuxPlatform()` 给出平台事实；`PopupPanel` 只在选区助手那一行、只在 Linux 上显示不支持提示。设置页不再让用户以为“按了没反应是坏了”。
- **运行前提拆成三句，不做统一句**：提醒＝退出期间到点不补发（下次启动 `markMissed`）；维护任务＝下次启动补跑；渠道网关＝退出后没人代答。三句各自落在提醒中心／数据健康／Channels 屏。**“需保持应用运行”这种统一提示被明确判为不做**：写在维护任务屏就是谎话（它是补跑）。这是口径修正，不是漏项。
- **2a 尾巴已修（V4-Iter-431）**：用量导出 CSV 的“估算花费”列不再把算不出的金额写成 0，屏上弹窗与 CSV 两个出口口径一致；预算硬阻断文案的货币符号跟随设置里的币种，不再写死在字典串里。

### 2.2 2b：零命中与来源分数（已完成；真机待补）

- 来源块不再由 `sources.length > 0` 倒推。`MessageRetrieval` 落库后，界面只念这份事实：`!searched`＝“知识库未启用”，`hits === 0`＝“查过但未命中”，`failed`＝“检索失败”。
- `score` 是 RRF 融合分，由 `chunksToSources` 原样搬运；缺字段就不显示徽标，不补 0、不出 NaN。来源列表底部有一句口径说明：同轮内越大越相关，不是余弦相似度、不是概率，跨轮／跨库不可比。
- 0 命中也会写 `retrieval` 信封，否则下次重读会退化成“没查”；旧纯数组行保持 `undefined`，旧消息“不知道”不等于“未启用”，界面一句状态句都不说。

### 2.3 2c：审批落库与出网清单（已完成；明细与导出已交付，真机目视完成、WPS 未验）

- **审批决定有独立账本**：`approval_events`（v53）回答“谁批的、批了多大范围、什么时候、结果如何”。它不挂在 `agent_traces` 上，因为 trace 是每步一行、且“重新运行”会按 request 删掉；粒度不对，还会随重跑消失。
- **记账口径**：只记用户参与过决定的事件——用户批准、用户拒绝、超时拒绝、会话白名单放行（此前的授权）、策略拒绝。自动执行成功、用户没被打扰的调用不记账（trace 已有，不重复存）。参数先按键名脱敏，再走文本级规则，2,000 字符封顶，另存 `args_digest`；不存返回值、不存 MCP env／headers。
- **写失败 fail-open**：工具照原决定执行，但每进程向渲染端广播一次可见提示，失败次数进数据健康。删除会话级联删除审批事件；留存 180 天／10 万行。
- **出网清单屏**：30 条出口从 `OUTBOUND_ENTRIES` 现量枚举，覆盖测试递归扫 `src/main` 的调用点，新增 `fetch`／`safeFetch`／`new WebSocket`／`autoUpdater`／`webdav` 未登记即变红；豁免只有传输层 `safe-fetch.ts`，写在注册表内可 review。读不到配置显示“读取失败”，不画成“未配置”。
- **2c-3 明细与导出已交付**（V4-Iter-432／V4-Iter-435，`98332ba`）：可按会话／决定／时间筛选逐条查看，并导出当前筛选结果为 JSON／CSV（主进程保存、2,000 行硬上限、只导 `args_redacted`／`args_digest`、不走网络）。**真机目视（V4-Iter-501／清单 B258–B261，2026-11-16）**：筛选、主进程保存框与取消、CSV BOM／转义、2,000 行截断提示均按真机读数通过；Excel 已实开 CSV（4 行×12 列，中文与逗号／引号／真实换行均正确）。**仍未验**：本机未装 WPS，WPS 打开 CSV 那一半未验。出网屏 v2 已支持 allowlist 阻断（`OUTBOUND_HOST_BLOCKED`）与域名规范化；导出仍未做。

## 6. 本地小模型的降级形态

本仓实测记档：**Ollama 不能当 tool-calling harness；1.5B 会把注入材料当指令回话；3B 起步才具备可用性，但仍会被资料带偏**（`docs/verify-checklist.md:258`、`docs/v4-iteration-ledger.md:3359`）。买断＋BYOK 人群里低配机占比不低，所以“同一套 Agent 能力全量下放”是假的。

产品必须显式分档：小模型走文本协议／纯技能路径；第一轮前就说明“**这台机器上它不会调工具**”，而不是让用户以为坏了；自动隐藏工具循环、截图问答、长任务续跑，只保留聊天、知识库、技能。文本协议不是万能补丁，它降低工具调用可靠性，验收要按纯文本任务算。相关现状见 `zh.ts` 的文本协议开关与低配推荐档位。**能力检测本身归 P0-4b，已落地（V4-Iter-500）**：四档判定会明确说“这台机器上它不会调工具”，但只提示，不隐藏入口；自动隐藏工具循环、截图问答、长任务续跑仍未做，不冒充已经完成分档。

**判定档 D1（所有“行为可见”类验收统一用）**：默认判定机为 **Windows 11 x64 真机**（验收记录写明 CPU／RAM／系统版本）；默认模型为本轮验收预先写死的一个 `provider + model`——本地不低于 3B，或任一 BYOK 云端模型；同一批复验不得换机换模型。macOS 真机只作补充档。**排除**：1.5B、Ollama 作为 tool-calling harness。低配档的验收不是“行为出现”，而是“界面明确说不会调工具，且纯聊天／知识库／技能可用”。

## 7. 明确不做什么

1. **云端常驻 Agent（关电脑继续跑）**：云电脑、沙箱、计费、滥用治理都要持续投入，买断覆盖不了。
2. **Computer Use / 自动点击操作系统**：适配与安全成本极高，当前权限模型撑不起，做了就是把用户机器变成风险面。**边界要说清**：P1-4 的截图是用户主动触发的一次性捕获，不等于自动操作 OS；一旦滑向“替用户点”，就归入本条。
3. **自建托管模型与免费额度池**：GPU 与合规成本会击穿买断结构；模型必须留在用户账上。
4. **账号云同步与多人实时协同**：需要服务端与持续订阅，且与“数据自己留着”冲突。
5. **市场数量竞赛、多代理并行演示**：包装层，不解决发现与质量问题。

## 8. 商业形态：买断怎么成立

**买断成立的前提只有一句：把推理成本从厂商账本上拿掉。** 只要模型调用仍由厂商垫付，买断就是伪命题。

- **更新承诺（目标形态，当前不作为销售权益）**：目标形态是买断含 12 个月更新、到期后当前版本永久可用。**字段已能表达**（`expires_at`＋`updates_until`，V4-Iter-488），但还不能写成销售承诺：便携版不能自动更新（设计性拒绝），安装包无代码签名，“12 个月更新”对便携用户只剩手动下载；签发链默认签 v1（更新期跟随使用截止），只有显式传更新期才签 v2，而 v2 件在 1.2.8 及更早客户端验签失败 ⇒ 新版客户端铺开前不能把默认切到 v2。发布流程、代码签名与过渡完成前，销售页不写“12 个月更新”“永久可用”。
- **反盗版**：离线签名＋可选硬盘绑定已实现；服务端已有管理员解绑通道 `POST /v1/admin/unbind`（请求头 `x-admin-token` 必须匹配 `LICENSE_ADMIN_TOKEN`，未配置则 503 关闭；清 `fingerprint` / `bound_at` / `license_id` / `license_json` 并置回 `unused`）。解绑只让卡密重新可用于新机器，已签发的旧 license 文件仍可在原指纹机器上离线使用至其 `expires_at`，这是离线授权无法远程吊销的边界。**“宽限期”代码零字段、“席位”代码零字段；客户端没有自助解绑入口**。`LICENSE_CLEAR` 只是本地清除，不能让卡密在服务端解绑；换机需卖家走 API 或 CLI。不做强制联网校验，否则“本地优先”先破产。
- **到期语义**：`expires_at` 是使用截止，`updates_until` 是更新截止（历史 v1 件缺失时回退为 `expires_at`）。`license.ts` 运行时重判两件事：① `updates_until` 到期只停更新——`update-manager.ts` 在 init／check／download／quitAndInstall 四处拒绝，已安装版本继续可用，专业版两条数量上限与 features 不受影响；② `expires_at` 到期仍按现状判过期（`getStatus().valid=false`、`hasFeature()` 返回 false、`isPaidPlan()` 返回 false）。**“停更不停用”指更新期结束后使用期内的能力不变，不是把 `expires_at` 改成永不过期。** 本机更新期高水位（`data/userdata/license-updates.json`）与许可证独立，清除许可证不清它；它是本地状态，删除应用数据会重置；便携版仍可手动下载新版本，应用内无法拦截。
- **指纹口径**：`disk_fingerprint` 为空＝不绑定设备；声明了绑定但本机读不到指纹时，`license.ts` 的指纹校验判为不匹配并拒绝（不是“读不到就不绑定”）。`hardware.ts:503` 的注释“返回 null 时 License 不绑定设备”与此行为不一致，后续应改注释或改行为，当前以代码为准。
- **经济底线**：更新续费比例必须用前 12 个月真实数据验证；达不到就缩短大版本周期或提高首发价，而不是偷偷改订阅。本文不编价格、不编市场份额。
- **与竞品订阅的取舍**：竞品卖“算力＋云＋模型新鲜度”，我们卖“本地执行＋数据主权＋永久授权”。会失去“付款即用、不想管 Key”的人；接受，因为服务他们必然变成云成本。留下的人更愿意把敏感资料放进来，这才是留存来源；代价是收入前置，必须靠大版本和企业单续命。竞品数据未联网复核，只作待核假设。
