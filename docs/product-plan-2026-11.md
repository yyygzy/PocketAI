# 产品改造计划（2026-11，修订版 2）

> 修订基准：2026-11-06 工作树（已包含 V4-Iter-410～427 的落地提交）。行号会随代码漂移，所以关键断言同时写函数名／常量名；本文只把能在 `src/` 里回源的事实当作论据。

## 0. 一句话定位

**PocketAI 是一台装在自己电脑里的、可审计的 AI 工作台：模型你选，数据你留，工具你批，授权买一次就归你。**

它不是更便宜的 ChatGPT 桌面壳，也不是云端代跑 Agent。用户选它而不是 ChatGPT 桌面，只应该因为三件事：模型与推理可以完全归自己（BYOK／本地）、资料与执行不离开本机、每个工具动作可审批可回溯。换不来这三样，这个产品就没有存在理由。

**现状判断：入场券已补齐大半；“已有地基”仍会被误判成缺口；真正的剩余断点是普通聊天与 Agent 的合流、可回放的执行层，以及商业章节里几条代码还兑现不了的承诺。**

## 2. 产品诚实性：界面在沉默或说谎

P0-2 原本是一条，里面混着五种成本不同的东西。本文把它拆成 2a／2b／2c，**拆开的理由不是项目管理偏好，而是防止季度末出现“这条做了一半但看起来做了”**：2a 只动文案与渲染分支，2b 要跨检索→落库→渲染，2c 要动表与出网枚举；捆在一起时，最容易发生的就是 2a 的文案先上、2b／2c 的数据层没跟上，而界面已经“看起来有了”。

### 2.1 2a：纯文案与空态（已完成，仍有两处尾巴）

- **单价表为空不显示金额**：`UsagePanel.tsx` 的金额位、超额判定、进度条都按“价表非空”分档；价表为空时只显示“未配置单价”，不再出现裸 `¥` 或 `¥0`。同时收口了费用趋势、明细弹窗合计、问答气泡用量三处同形裸符号。
- **Linux 取词不支持明说**：`utils/shortcuts.ts` 的 `isLinuxPlatform()` 给出平台事实；`PopupPanel` 只在选区助手那一行、只在 Linux 上显示不支持提示。设置页不再让用户以为“按了没反应是坏了”。
- **运行前提拆成三句，不做统一句**：提醒＝退出期间到点不补发（下次启动 `markMissed`）；维护任务＝下次启动补跑；渠道网关＝退出后没人代答。三句各自落在提醒中心／数据健康／Channels 屏。**“需保持应用运行”这种统一提示被明确判为不做**：写在维护任务屏就是谎话（它是补跑）。这是口径修正，不是漏项。
- **2a 仍剩两处**：用量导出 CSV 的“估算花费”列仍读库里那个 0（要分清必须让落库行带“单价是否命中”标记，跨 schema＋usage-service＋导出）；预算硬阻断文案的货币符号仍写死在字典串里。两处已记候选，不在“已完成”里冒充完成。

### 2.2 2b：零命中与来源分数（已完成；真机待补）

- 来源块不再由 `sources.length > 0` 倒推。`MessageRetrieval` 落库后，界面只念这份事实：`!searched`＝“知识库未启用”，`hits === 0`＝“查过但未命中”，`failed`＝“检索失败”。
- `score` 是 RRF 融合分，由 `chunksToSources` 原样搬运；缺字段就不显示徽标，不补 0、不出 NaN。来源列表底部有一句口径说明：同轮内越大越相关，不是余弦相似度、不是概率，跨轮／跨库不可比。
- 0 命中也会写 `retrieval` 信封，否则下次重读会退化成“没查”；旧纯数组行保持 `undefined`，旧消息“不知道”不等于“未启用”，界面一句状态句都不说。

### 2.3 2c：审批落库与出网清单（已完成；明细／导出仍未做）

- **审批决定有独立账本**：`approval_events`（v53）回答“谁批的、批了多大范围、什么时候、结果如何”。它不挂在 `agent_traces` 上，因为 trace 是每步一行、且“重新运行”会按 request 删掉；粒度不对，还会随重跑消失。
- **记账口径**：只记用户参与过决定的事件——用户批准、用户拒绝、超时拒绝、会话白名单放行（此前的授权）、策略拒绝。自动执行成功、用户没被打扰的调用不记账（trace 已有，不重复存）。参数先按键名脱敏，再走文本级规则，2,000 字符封顶，另存 `args_digest`；不存返回值、不存 MCP env／headers。
- **写失败 fail-open**：工具照原决定执行，但每进程向渲染端广播一次可见提示，失败次数进数据健康。删除会话级联删除审批事件；留存 180 天／10 万行。
- **出网清单屏**：26 条出口从 `OUTBOUND_ENTRIES` 现量枚举，覆盖测试递归扫 `src/main` 的调用点，新增 `fetch`／`safeFetch`／`new WebSocket`／`autoUpdater`／`webdav` 未登记即变红；豁免只有传输层 `safe-fetch.ts`，写在注册表内可 review。读不到配置显示“读取失败”，不画成“未配置”。
- **仍未做**：审批明细的按会话／时间筛选、逐条查看与导出；出网屏 v1 只读，无阻断／allowlist／导出。

### 2.4 仍然沉默或可能说谎的地方

1. 审批事件已落库，但没有界面能逐条查“谁批的”；数据在库里，用户看不见。2c-3 不做，这条只能算“可回溯”的一半。
2. 零命中三态已上屏，但真机知识库问答还没跑；“CI 绿”不等于“真机上用户能看懂”。
3. 回放状态有字段，渲染端没消费；“能回放”目前是数据层事实，不是用户能看到的能力。
4. “授权过期只停更不停用”与 `license.ts` 的行为相反（过期即失去付费功能）；在拆出 `updates_until` 之前不能这么写。
5. 单价为空时屏上不编金额，但 CSV 导出仍会把“算不出”写成 0；两个出口口径不一致。

## 6. 本地小模型的降级形态

本仓实测记档：**Ollama 不能当 tool-calling harness；1.5B 会把注入材料当指令回话；3B 起步才具备可用性，但仍会被资料带偏**（`docs/verify-checklist.md:258`、`docs/v4-iteration-ledger.md:3359`）。买断＋BYOK 人群里低配机占比不低，所以“同一套 Agent 能力全量下放”是假的。

产品必须显式分档：小模型走文本协议／纯技能路径；第一轮前就说明“**这台机器上它不会调工具**”，而不是让用户以为坏了；自动隐藏工具循环、截图问答、长任务续跑，只保留聊天、知识库、技能。文本协议不是万能补丁，它降低工具调用可靠性，验收要按纯文本任务算。相关现状见 `zh.ts` 的文本协议开关与低配推荐档位。

**判定档 D1（所有“行为可见”类验收统一用）**：默认判定机为 **Windows 11 x64 真机**（验收记录写明 CPU／RAM／系统版本）；默认模型为本轮验收预先写死的一个 `provider + model`——本地不低于 3B，或任一 BYOK 云端模型；同一批复验不得换机换模型。macOS 真机只作补充档。**排除**：1.5B、Ollama 作为 tool-calling harness。低配档的验收不是“行为出现”，而是“界面明确说不会调工具，且纯聊天／知识库／技能可用”。

## 7. 明确不做什么

1. **云端常驻 Agent（关电脑继续跑）**：云电脑、沙箱、计费、滥用治理都要持续投入，买断覆盖不了。
2. **Computer Use / 自动点击操作系统**：适配与安全成本极高，当前权限模型撑不起，做了就是把用户机器变成风险面。**边界要说清**：P1-4 的截图是用户主动触发的一次性捕获，不等于自动操作 OS；一旦滑向“替用户点”，就归入本条。
3. **自建托管模型与免费额度池**：GPU 与合规成本会击穿买断结构；模型必须留在用户账上。
4. **账号云同步与多人实时协同**：需要服务端与持续订阅，且与“数据自己留着”冲突。
5. **市场数量竞赛、多代理并行演示**：包装层，不解决发现与质量问题。

## 8. 商业形态：买断怎么成立

**买断成立的前提只有一句：把推理成本从厂商账本上拿掉。** 只要模型调用仍由厂商垫付，买断就是伪命题。

| 卖什么 | 代码今天能兑现的 | 不能兑现／待实现 | 处置 |
|---|---|---|---|
| 个人永久授权 | 离线签名许可证、可选硬盘绑定、离线激活 | 许可证只有 `expires_at`，没有 `updates_until`；“当前版本永久可用＋12 个月更新”无法用现有字段表达；过期即 `hasFeature=false` | 先改许可证字段与语义，再写“永久” |
| 专业版 | 工具策略屏、`fs_write` 单文件还原、变更清单（只读）、审批落库 | 审计导出未做（2c-3）、批量任务未做；shell／MCP 不可回滚 | 只按已交付的卖；未交付的写进路线图，不写进权益 |
| 团队／企业 | 离线激活可用 | 席位、宽限期、解绑通道、审计导出、更新截止均无 | **本轮不售**；成本需重估 |
| 精选扩展包 | — | 签名打包器未做（P2-3） | 计划项，不预售 |

- **更新承诺（目标形态，当前不作为销售权益）**：目标形态是买断含 12 个月更新、到期后当前版本永久可用。**当前代码兑现不了这条**：便携版不能自动更新（设计性拒绝），安装包无代码签名，“12 个月更新”对便携用户只剩手动下载；且“永久可用”与“12 个月”在许可证里是同一个 `expires_at`。在补发布流程与许可证字段前，销售页不写“12 个月更新”“永久可用”。
- **反盗版**：离线签名＋可选硬盘绑定已实现；**“宽限期”代码零字段、“席位”代码零字段、没有解绑 API**。`LICENSE_CLEAR` 只是本地清除，不能让卡密在服务端解绑；换机只能卖家重签。不做强制联网校验，否则“本地优先”先破产。
- **到期语义**：`license.ts:187-204` 运行时重判 `expires_at`，过期后 `getStatus().valid=false`、`hasFeature()` 返回 false、`isPaidPlan()` 返回 false ⇒ 付费功能停止。**“停更不停用”不是现状**；要实现它，必须把“使用截止”与“更新截止”拆成两个字段，并明确过期后哪些功能仍可用。
- **指纹口径**：`disk_fingerprint` 为空＝不绑定设备；声明了绑定但本机读不到指纹时，`license.ts:170-178` 判为不匹配并拒绝（不是“读不到就不绑定”）。`hardware.ts:503` 的注释“返回 null 时 License 不绑定设备”与此行为不一致，后续应改注释或改行为，当前以代码为准。
- **经济底线**：更新续费比例必须用前 12 个月真实数据验证；达不到就缩短大版本周期或提高首发价，而不是偷偷改订阅。本文不编价格、不编市场份额。
- **与竞品订阅的取舍**：竞品卖“算力＋云＋模型新鲜度”，我们卖“本地执行＋数据主权＋永久授权”。会失去“付款即用、不想管 Key”的人；接受，因为服务他们必然变成云成本。留下的人更愿意把敏感资料放进来，这才是留存来源；代价是收入前置，必须靠大版本和企业单续命。竞品数据未联网复核，只作待核假设。
