## 1. 项目概览

### 1.1 产品定位

本地优先（local-first）、可随身携带（portable）、跨系统（Windows + Linux）的个人 AI 工作台。全部数据在用户本地一个文件夹内，支持 U 盘携带、离线激活、本地加密。

### 1.2 技术栈

| 层 | 技术 |
|---|---|
| 外壳 | Electron 44（`contextIsolation: true`，`nodeIntegration: false`） |
| 构建 | electron-vite 4 + electron-builder 26 |
| 语言 | TypeScript 5.6（strict） |
| 渲染层 | React 18 + Tailwind CSS 3 |
| 数据库 | better-sqlite3-multiple-ciphers 13（SQLCipher 兼容，同步 API） |
| 向量检索 | 纯 JS 余弦相似度（**不使用** sqlite-vec 原生扩展，规避跨平台二进制分发问题） |
| 更新 | electron-updater 6 + 自研 asar 块级增量补丁（RSA 签名） |
| 模型协议 | OpenAI Chat Completions 兼容（SSE 流式） |
| MCP | 自研零依赖轻量 JSON-RPC 实现 |
| Markdown | react-markdown + remark-gfm/math + rehype-highlight/katex + mermaid |
| 文档解析 | pdf-parse / mammoth(docx) / xlsx / cheerio |
| 备份 | archiver(zip) + WebDAV（webdav 包），支持加密与增量 |

### 1.3 仓库顶层结构

```
PocketAI/
├── src/
│   ├── main/        # 主进程（Node 环境，全部系统能力）
│   ├── preload/     # 预加载（唯一桥，contextBridge 暴露 window.pocketai）
│   ├── renderer/    # 渲染层（React，浏览器环境，禁止 Node API）
│   └── shared/      # 三端共享类型与纯函数（types.ts / snippet.ts）
├── extensions/      # 数据型扩展：assistants/*.json、skills/*.json（启动时同步入库）
├── build/           # 打包资源（icon.png）+ 发行侧密钥/测试 license（不入库私钥）
├── scripts/         # 构建、签发、检查、测试脚本
├── docs/            # 手册
├── electron-builder.linux.yml   # Linux AppImage 独立完整配置
├── electron.vite.config.ts
└── package.json     # Windows 构建配置在 build 段
```

## 2. 开发环境搭建

### 2.1 前置要求

- **Node.js 22.x**（推荐与 Electron 44 的 Node 版本对齐；≥ 20 亦可）
- **npm 10+**
- Windows 10/11 或 Linux x64
- 网络可访问 npm registry；国内建议配置 npmmirror（见 11.4）

### 2.2 安装与启动

```bash
npm ci            # 或 npm install；postinstall 自动 electron-builder install-app-deps 重建原生模块
npm run dev       # electron-vite dev，热更新开发
```

常用命令：

```bash
npm run typecheck          # tsc --noEmit，提交前必过
npm run build              # electron-vite build（仅编译，不打包）
npm run dist               # Windows：NSIS 安装版 + portable 便携版 → dist/
npm run dist:nsis          # 仅安装版
npm run dist:portable      # 仅便携版
npm run dist:linux         # Linux AppImage → dist/（见 9.3 的宿主限制）
npm run license            # 激活码交互式签发台
node scripts/release-check.mjs   # 发布前全量检查（可加 --quick）
```

### 2.3 开发期数据位置

- 未打包运行时 `APP_ROOT = process.cwd()`（仓库根），数据落在仓库根 `data/`（已被 gitignore）。
- 可用环境变量 `POCKETAI_APP_ROOT` 覆盖根目录用于测试。

## 3. 整体架构

### 3.1 三进程模型

```
┌──────────────────────────────────────────────────────────┐
│ Renderer（React，浏览器环境）                              │
│  App.tsx（主窗） / DetachedApp.tsx（独立窗） / PopupApp    │
│  只能通过 window.pocketai.* 调主进程，禁止 Node API         │
└────────────────────────┬─────────────────────────────────┘
                         │ contextBridge（preload/index.ts）
                         │ 类型化 API：invoke + 事件订阅
┌────────────────────────▼─────────────────────────────────┐
│ Main（Node 环境）                                          │
│  index.ts 启动编排 → ipc/index.ts 全部 IPC 注册            │
│  业务子系统：chat / agent / knowledge / crypto / lock …   │
│  数据层：better-sqlite3（同步）+ repositories              │
└──────────────────────────────────────────────────────────┘
```

**安全基线不可破坏：**

- `contextIsolation: true` + `nodeIntegration: false` + `sandbox` 默认策略；
- 渲染层一律用浏览器标准 API（如平台检测用 `navigator.userAgent`，禁止 `process.platform`）；
- 渲染层禁止 `window.prompt()`（Electron 不支持会静默失败）；
- 所有系统能力经 IPC 白名单下发，IPC 入参在主进程校验。

### 3.2 启动链路（main/index.ts）

1. 单实例锁（`requestSingleInstanceLock`），第二实例激活已有窗口；
2. `portable.ts` 计算 `APP_ROOT` 并 `ensureDirs()`；
3. `database.ts` 打开/创建 DB 并执行迁移链（当前 v17）；
4. `master-key.ts` 按加密模式初始化（`none` 直接解锁 / `db` 等待密码）；
5. 同步内置助手/技能（extensions → DB）；
6. 创建主窗口、注册 IPC、启动锁屏服务、保活、更新检查等；
7. 渲染层启动后查询向导状态（未完成首导向 / 换机重检）。

### 3.3 窗口体系

| 窗口 | 入口 | 说明 |
|---|---|---|
| 主窗口 | `renderer/src/main.tsx → App.tsx` | 侧边栏 + 标签栏 + Workspace |
| 独立窗口 | `detached.html → DetachedApp.tsx` | 路由 `#/detached?module=xxx`，单模块全屏；锁屏状态与主窗广播联动 |
| 解锁窗 | `unlock.html → unlock.tsx` | DB 加密时启动先出解锁窗，置顶抢焦点 |
| 悬浮窗 | `popup/PopupApp.tsx` | 快捷唤起小窗 |

窗口管理：`main/windows/detached.ts`、`main/popup.ts`。

### 3.4 标签与会话

- 主窗口支持多标签（Tab），布局持久化在 `localStorage`（key `pocketai.tabs.v1`，只存 moduleId/title/pinned + 激活位置）；
- 对话内部有**消息分支**：以 `batch_id`（= requestId）分组，`buildContext` 只取每轮激活分支；重新生成是非破坏式的，支持并排对比（BranchCompare）。

## 4. 核心子系统详解

### 4.1 数据层（db/）

- `database.ts`：单例连接，迁移链数组 `MIGRATIONS`（v1→v17），记录表 `schema_migrations`；启动时幂等补齐。
- `repositories/`：一表一 repo，SQL 全部参数化；主进程其他模块只依赖 repo，不直接写 SQL。
- 关键表：providers / assistants / skills / conversations / messages / kb(_docs/_chunks) / notes / mcp_servers / images / translations / sandboxes / app_config。
- `app_config` 是通用 KV（JSON 值），存加密模式、salt、自动锁屏超时、WebDAV 配置等。

### 4.2 加密体系（crypto/）

**四级加密概念在本项目的落地：none / db（整库 SQLCipher）/ field（字段级，始终启用）。**

| 文件 | 职责 |
|---|---|
| `master-key.ts` | 内存密钥管理。`none` 模式用固定口令+固定盐 scrypt 派生固定字段密钥（仅弱混淆，源码公开可复现，注释已声明）；`db` 模式由主密码+salt 派生 32 字节 masterKey |
| `index.ts` | 原语：scrypt 派生、AES-256-GCM 加解密 |
| `field-encrypt.ts` | 字段级加解密（API Key、WebDAV 密码等） |
| `secret-store.ts` | 密文存取封装 |
| `recovery-key.ts` | 恢复密钥生成与校验（忘主密码时的补救） |
| `credential-rotation.ts` | 凭据轮换 |
| `clipboard-guard.ts` | 剪贴板敏感内容定时清除 |
| `unlock-coordinator.ts` | 解锁流程协调（主窗/解锁窗/DB PRAGMA key） |

**关键性质（可移植性的生死线）：**
- 机器指纹**不参与**任何密钥派生，只用于换机检测；
- 无密码模式密钥任何机器可复现 → 换电脑直接读；
- 主密码模式 salt 存在数据目录（config.json 优先的双通道）随 U 盘走 → 换机输密码即解。
- 固定口令/盐一旦修改，所有无密码模式落盘字段密文与 WebDAV 密文全部失效，**禁止改动**。

### 4.3 隐私锁（lock/）

`lock.ts` 是状态机 `unlocked ↔ locked`，触发源：`manual | auto-timeout | app-hidden | os-sleep`。

- `autoLockTimeout` 存 app_config key `auto_lock_timeout`（ms，0=永不）；
- 活跃上报：渲染窗监听 mousemove/keydown，节流 5s 调 `LOCK_MARK_ACTIVE`，所有窗口（含 detached）都要参与；
- 每 10s 检查一次超时；
- 锁定时：广播 `LOCK_STATE_EVENT` → 各窗显示遮罩并 `inert` 冻结背景 DOM → 主进程清除内存密钥；
- `ipc-gate.ts`：锁定期间拦截敏感 IPC。

IPC：`LOCK_GET_STATUS / LOCK_LOCK / LOCK_UNLOCK / LOCK_SET_AUTO_TIMEOUT / LOCK_MARK_ACTIVE`。
手动锁屏入口：Ctrl/Cmd+L（App.tsx、DetachedApp.tsx 各有监听）、Sidebar 底部按钮。

### 4.4 便携性（portable.ts）

`APP_ROOT` 解析优先级（务必理解，改动会破坏便携性）：

1. `POCKETAI_APP_ROOT`（测试覆盖）
2. `APPIMAGE`（Linux：`dirname(APPIMAGE)`，因为挂载点只读）
3. `PORTABLE_EXECUTABLE_DIR`（Windows portable 自解压运行时注入；**不能**锚定 `app.getPath('exe')`，那是 %TEMP% 解压目录，拔 U 盘即丢）
4. 打包后 exe 所在目录（NSIS 安装版）
5. `process.cwd()`（开发）

`isPortableRuntime()`：win 看 `PORTABLE_EXECUTABLE_DIR`，linux 看 `APPIMAGE`。所有"是否便携/能否打 asar 增量补丁/更新文案"的判定统一用它。

数据路径：`data/app.db`、`data/vectors.db`（预留）、`data/config.json`、`data/attachments/`、`data/logs/`、`extensions/`、`runtime/`。

### 4.5 Provider 与对话（providers/ + chat/ + agent/）

- Provider 全部按 OpenAI 兼容协议抽象（`openai-compatible.ts`），`manager.ts` 管理多服务商；支持拉模型列表、连通性测试。
- `chat-service.ts`：消息收发、SSE 流式 chunk、中止（abort）、`concurrency.ts` 并发控制；事件经 preload 推给渲染（onChatChunk/Done/Error）。
- `agent/engine.ts`：工具调用循环（ReAct 风格）；`tool-approval.ts` 管风险工具人工审批。
- 工具体系见 4.6。

### 4.6 工具与沙箱（tools/ + sandbox/ + mcp/）

工具注册：`tools/registry.ts` 汇总 `BUILTIN_TOOLS + getFsTools() + getShellTools()` + MCP 动态工具。

| 文件 | 工具 |
|---|---|
| `builtin.ts` | time.now / calculator / web.fetch / web.search / js.eval |
| `websearch.ts` `websearch-config.ts` | 联网搜索（可配） |
| `weather.ts` | weather.query |
| `calendar-ics.ts` | calendar_read |
| `fs-tools.ts` | fs_list/fs_read/fs_write |
| `shell-tools.ts` `shell-config.ts` | shell_exec（分级管控） |
| `sandbox/js-eval-runner.ts` | 无文件/网络权限的隔离 JS 运行 |
| `mcp/manager.ts` `json-rpc.ts` | 零依赖 MCP 客户端；`python-env.ts` 管 MCP Python 环境 |

**文件工具安全链（必须保留）：**
- 仅当 `agent.workspace_dir` 已设置才注册；
- 路径处理：`posix.normalize → resolve → 工作目录前缀检查 + NUL 检查`，阻断 `../`、绝对路径、UNC、`%SystemRoot%` 等环境变量展开、`^` 等特殊字符。

**Shell 安全链：**
- 命令分 deny / confirm / allow 三类；deny 名单（format、`del c:\windows` 等）直接阻断；
- Windows 用 `cmd /d /s /c`，Unix 用 `sh`；输出 32KB 截断；独立超时 + AbortSignal 杀进程树；
- `shell_exec` 默认关闭，需助手设置显式开启；
- 审批对话框显示完整命令与风险，5 分钟超时自动拒绝。
- 工具结果统一截断：超 2000 字符截断并提示，防止 token 溢出。

### 4.7 知识库 RAG（knowledge/）

`parsers/`（PDF/docx/xlsx/text 统一入口）→ `chunker.ts`（切块）→ `embedding.ts`（调用 provider embedding）→ `ingestion.ts`（入库 kb_chunks）→ `rag.ts`（检索：纯 JS 余弦相似度 top-k 拼上下文）。

选纯 JS 相似度而非 sqlite-vec 是为避免 Electron 跨平台原生 .node 分发，改动需重新评估发布体积与双系统验证。

### 4.8 License 离线激活（license/ + scripts/）

- 非对称：发行侧私钥 `build/license-private.pem`（**严禁入库/打进包**，已在 .gitignore）签名，应用内置公钥 `src/main/license/public-key.ts`（DER base64，SPKI）验签。
- 载荷字段（SIGN_FIELDS，签发与验签的 canonicalize 必须一致）：`expires_at, features, issued_at, license_id, owner, plan, version`；规范化为 `k=v&...` 后 RSA-SHA256 签名。
- plan：`free / pro / enterprise`；`hasFeature()` 对 enterprise 直接放行（万能钥匙）。
- 免费额度门控：`LITE_LIMITS = { assistants: 3, knowledgeBases: 1 }`。
- 密钥对生成：`scripts/generate-license-key.js`（换钥后需更新 public-key.ts，旧码全部失效）。
- 签发：`npm run license`（交互台）或 `scripts/sign-license.js`；共享核心在 `scripts/lib/issue-license.js`，两个入口不得分叉。
- 产物在 `licenses/`（gitignore，含用户姓名）。

### 4.9 更新（update-manager.ts + update/asar-patcher.ts）

- electron-updater 源：GitHub Releases `yyygzy/PocketAI`，channel `latest`；
- Windows 安装版：支持自研 **asar 块级增量补丁**（`make-asar-patch.js` 生成 diff，RSA 签名，`asar-patcher.ts` 下载 `asar-patch-{from}-{to}.json.gz` 并应用）；
- **asar 增量仅 Windows 安装版**：便携版与 Linux AppImage 跳过（`isPortableRuntime()` 判定）；
- Linux：AppImage 走 electron-updater 全量（需要 `latest-linux.yml`）；非 AppImage Linux 返回 unavailable 提示手动下载；
- 更新前平台判定全部统一走 `isPortableRuntime()`。

### 4.10 备份（backup/）

- 本地 zip 备份 / 加密备份（独立口令）；
- WebDAV：配置加密存 app_config，支持定时调度（backup-scheduler）、全量与**增量**备份、列表/恢复/删除、连接测试；
- 备份含 manifest；恢复是版本迁移的重要入口（旧数据 → 新库 → 跑迁移链）。

## 5. IPC 与 preload 开发规范

1. 频道常量统一定义在 `shared/types.ts`（IPC 枚举），主/预加载/渲染共享，禁止散落字符串。
2. 新增能力的完整四步：
   - `shared/types.ts`：频道名 + 请求/响应类型；
   - `main/ipc/index.ts`：`ipcMain.handle(...)`，**入参全部校验**（类型、长度、路径白名单）；
   - `preload/index.ts`：在 `window.pocketai` 暴露类型化方法 / 事件订阅返回取消函数；
   - 渲染层调用；`renderer/src/types/pocketai.d.ts` 保持类型同步。
3. 主进程 → 渲染的事件用 `webContents.send`，preload 暴露 `onXxx(handler): () => void`（返回退订）。
4. 锁屏期间新增的敏感 IPC 必须在 `lock/ipc-gate.ts` 加拦截。
5. 渲染层禁止自己拼路径/执行命令；风险操作必须走审批流（参考 ToolApprovalDialog）。

## 6. 数据库与迁移规范

当前 `LATEST_SCHEMA_VERSION = 17`。

**加一个新迁移（v18）的规则：**

1. 在 `database.ts` 的 `MIGRATIONS` 末尾追加 `{ version: 18, name: 'xxx', up(db) {...} }`，**绝不修改历史迁移**；
2. 迁移必须幂等（`CREATE TABLE IF NOT EXISTS`、加列前先查 pragma）；
3. 涉及数据回填的，写成"能重入"的批量语句；
4. 同步更新对应 repo 与 shared 类型；
5. 用 `scripts/check-migration.js` 验证；**旧数据升级回归**（真实 0.x/旧版本 data 目录：API 密钥解密、对话/知识库/技能完整性、解锁流程）是发布前必做项。

**备份兼容：** 恢复旧备份后同样要跑迁移链，因此迁移要能处理"更老形态"的数据。

## 7. 安全约束清单（硬规则）

以下来自项目已确立的不可违反约定，改代码前先对照：

1. 便携：所有数据在单一可移动文件夹；不依赖系统目录、注册表、cwd。
2. `contextIsolation: true` + `nodeIntegration: false`；渲染层零 Node API（平台检测用 `navigator.userAgent`）。
3. 文件系统工具：工作目录前缀校验 + posix normalize/resolve + NUL 检查；未设 workspace_dir 不注册。
4. Shell：deny/confirm/allow 三级；默认关闭；`cmd /d /s /c` / `sh`；32KB 截断；超时 + AbortSignal 杀进程树；防 `..`、UNC、环境变量、`^` 注入。
5. 工具审批：展示完整命令与风险，5 分钟无操作自动拒绝。
6. 工具结果超 2000 字符截断。
7. v1 不做内置终端/通用沙箱能力（js_eval 是受限求值器，不是 shell）。
8. License 完全离线 RSA 验签；私钥只在发行侧，禁止入库/进包。
9. 向量用纯 JS 余弦相似度，不引入 sqlite-vec 原生扩展。
10. MCP 协议零外部依赖、轻量实现。
11. 渲染层禁止 `window.prompt()`。
12. 更新源固定 GitHub Releases `yyygzy/PocketAI`，tag 格式 `v{version}`；asar 增量补丁仅 Windows 安装版。
13. 加密固定口令/盐不得修改（会使存量字段密文失效）。
14. 机器指纹不参与密钥派生。
15. 剪贴板敏感内容自动清除能力保留；锁屏遮罩用 inert 冻结背景。
16. 出站请求走 safe-fetch / 外链白名单；CSP 不可放开 unsafe-eval/remote script（业务需要的求值在主进程沙箱完成）。
17. 发布产物：Win 安装版+便携版、Linux AppImage；macOS 不在 v1 范围。

## 8. i18n 与 UI 约定

- 词条两文件必须同步：`renderer/src/i18n/zh.ts`（中文，默认）与 `en.ts`；新增 key 两边都加，缺失会回退显示 key 本身。

## 9. 构建与发布

### 9.1 Windows 构建（本地可做）

```bash
npm run dist        # → dist/PocketAI-<ver>-x64.exe（NSIS）+ -Portable-x64.exe + latest.yml + blockmap
```

配置在 `package.json > build`：appId `ai.pocket.desktop`；asar 开启；两个 better-sqlite3 包的 `.node` 走 asarUnpack；Windows 包排除 darwin/linux/linuxmusl prebuilds。

### 9.2 Linux 构建配置

`electron-builder.linux.yml` 是**完整独立配置**（不用 extends，平台差异覆盖不可靠）：AppImage x64、category Utility、artifactName `PocketAI-${version}-Linux-${arch}.${ext}`、排除 darwin/win32 prebuilds 保留 linux/linuxmusl。

### 9.3 ⚠️ Linux AppImage 不能在 Windows 宿主构建

electron-builder 26 的 AppImage 工具链（mksquashfs 等）只发布 Linux/macOS 宿主二进制，Windows 上打包必然失败（与开发者模式/symlink 无关）。**Linux 产物统一由 CI（ubuntu runner）构建**，不要在 Windows 本地死磕。

### 9.4 CI/CD（.github/workflows/release.yml）

两个 job：

- `Build Windows x64`（windows runner）：`npm ci` → `npm run dist` → 上传 artifact → tag 推送时创建 Release；
- `Build Linux AppImage`（ubuntu runner）：`npm ci` → `npm run dist:linux` → 上传 `*.AppImage/*.blockmap/*.yml`。

触发：
- 推送 `v*` tag → 构建 + 创建 GitHub Release（Release 步骤有 `if: startsWith(github.ref,'refs/tags/v')` 守卫，手动触发只验证构建不发版）；
- 支持 `workflow_dispatch` 手动验证。

Release 资产精确 glob（不要再用 `dist/*`，会带入 builder-debug.yml）：
- Windows：`dist/*.exe`、`dist/*.blockmap`、`dist/latest.yml`
- Linux：`dist/*.AppImage`、`dist/*.blockmap`、`dist/*.yml`

> 已知现象：electron-builder 26 在 Linux 不产 AppImage blockmap，Linux 更新走全量（不影响功能）。

### 9.5 标准发版流程

```bash
# 1) 机器检查（0 FAIL 才能继续）
node scripts/release-check.mjs

# 2) 人工清单（脚本 G 组会打印）：
#    旧数据升级回归 / 双机跨系统互通 / 杀软实测 / 锁屏联动 / Release 资产复查

# 3) 升版本号（package.json version，必须与 tag 对齐）
git add package.json && git commit -m "chore(release): vX.Y.Z"

# 4) 打 tag 推送 → CI 自动构建并发 Release
git tag vX.Y.Z
git push origin main
git push origin vX.Y.Z

# 5) 验收 Release：2 exe + AppImage + latest.yml + latest-linux.yml + blockmap；
#    旧版本应用"检查更新"能发现新版本
```

发布检查脚本（`scripts/release-check.mjs`）覆盖：版本/仓库一致性、构建配置、产物（含 AppImage offset 8 的 `AI` 魔数、latest*.yml、blockmap）、私钥未入库且**无 git 历史泄露**、签发→内置公钥验签闭环、工作树卫生、tsc + electron-vite build。

## 11. 故障排查手册

### 11.1 `npm run dev` 启动后没有窗口

按以下顺序排查（历史真实案例）：

1. **残留进程持单例锁**：任务管理器结束残留 electron，或 `taskkill /F /IM electron.exe`；单例锁失败应有提示弹窗。
2. **解锁窗被终端遮挡**：解锁窗会置顶抢焦点；确认不是停在解锁界面等密码。
3. **国产杀软误杀网络服务进程**：日志出现 `Network service crashed or was terminated` 多为腾讯电脑管家/360 行为，加入信任区后重启（与 `NetworkServiceInProcess` 开关无关，勿乱改）。
4. 看 `data/logs/` 启动日志与主进程控制台。

### 11.2 原生模块报错（better-sqlite3 ABI 不匹配）

```bash
npx electron-builder install-app-deps
```
postinstall 已自动执行；手动切 Electron 版本后必须重跑。

### 11.3 打包时 EPERM 写 Electron 缓存 / 删不掉 dist

- 构建会写 `%LOCALAPPDATA%\electron\Cache`，受限沙箱里要放行或在沙箱外执行；
- `dist/win-unpacked/resources/app.asar` 被杀软实时扫描长期句柄占用时：先结束 electron/PocketAI 进程；仍占用则把构建输出改到新目录（electron-builder API `build({ config: { directories: { output: 'dist-fresh' } } })`），稍后再清旧目录。

### 11.4 下载 Electron/构建工具超时（国内网络）

设置镜像后重试：
```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
```

### 11.5 本地打包意外尝试发布 GitHub（报缺 GH_TOKEN）

electron-builder 检测到环境里有 `CI=true` 会触发隐式发布。本地构建请清掉该变量（`Remove-Item Env:CI`）或显式 `--publish never`。**真正发布只走 CI。**

### 11.6 Linux 交叉构建 symlink 失败 / mksquashfs 错误

- symlink：Windows 需开"开发者模式"，但即使开了也打不了 AppImage（见 9.3），直接用 CI；
- Linux 本机打包：确认有 FUSE（AppImage 运行）与 squashfs 工具。

### 11.7 换机后数据打不开/密钥解密失败

- 确认 data 目录完整（尤其 config.json 里的 salt）；
- 无密码模式应直接可读；主密码模式确认输入的是同一主密码；
- 检查是否误改了 FIXED_KEY_PASSWORD/SALT；
- 用恢复密钥流程；仍不行用最近备份恢复。

### 11.8 更新不生效

- 确认 Release 资产齐全：`latest.yml`（Win）/`latest-linux.yml`（Linux）里的 path/sha512 与实际资产一致；
- 便携版/Linux 非安装形态本来就不走 asar 增量；
- electron-updater 依赖 GitHub API/下载可达性；
- tag 必须是 `v` + package.json version。
